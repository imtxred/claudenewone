# Отчёт по рекламным кабинетам

## ГЛАВНОЕ ПРАВИЛО

**Ничего не гасить и не менять. Только читать и докладывать.**

Решение о выключении кампаний и о бюджетах принимает только владелец.
Причина: его трекер лидов ловит больше конверсий, чем показывает Facebook,
поэтому высокий CPL в кабинете **не означает убыток**. Любая цифра CPL в отчёте —
это данные Facebook, и реальная может быть ниже.

Исключение одно: если владелец прямо в этом же сообщении просит что-то включить,
выключить или поменять бюджет — выполняю сразу, без переспрашивания. Но по
собственной инициативе, по итогам отчёта — никогда.

## Как собирать данные

### Порядок вызовов

1. `ads_get_ad_accounts` — убедиться, что `is_queryable: true` у всех трёх.
   Если false — показать `not_queryable_reason` и не дёргать дальше.
2. `ads_get_field_context` — **проверить имена полей перед запросом.** Не угадывать.
   Например, расход на уровне кампании это `spend`, а `amount_spent` — атрибут аккаунта.
   Инструмент возвращает канонические имена и то, по каким полям можно фильтровать и сортировать.
3. `ads_get_ad_entities` по каждому кабинету, `level: "campaign"`.

### Обязательные параметры

- `client_conversation_id` — 20 символов `A-Za-z0-9`, **один и тот же на все вызовы**
  внутри одного отчёта. Генерируется при первом вызове.
- `advertiser_request` — дословная формулировка владельца, его словами, без пересказа
  в технические термины.

### Три среза

| Срез | Параметр |
|---|---|
| Сегодня | `date_preset: "today"` |
| Вчера | `date_preset: "yesterday"` |
| Неделя | `date_preset: "last_7d"` |

Для выгорания дополнительно `date_preset: "last_7d"` с `time_increment: "1"` —
получить дневную разбивку и увидеть тренд, а не среднее.

### Поля

Запрашивать: `id`, `name`, `status`, `effective_status`, `spend`, `impressions`, `reach`,
`frequency`, `cpm`, `cpc`, `ctr`, `outbound_clicks_ctr`, `results`, `cost_per_result`,
`daily_budget`.

**Ограничения инструмента:**
- на уровне `ad_account` не работают `filtering`, `sort` и `cost_per_result` — поэтому level всегда `campaign`
- `time_increment` передаётся строкой: `"1"`, а не `1`
- один `breakdowns` на вызов; если с ним пусто — повторить без него
- `date_preset` и `time_range` вместе не передавать
- инструмент отдаёт подмножество, а не всё: чтобы взять и лучшие, и худшие — два вызова с обратной сортировкой

## Формат отчёта

### 1. Итог дня

Суммарный открут по трём кабинетам, суммарные лиды, средний CPL, сравнение со вчера
в процентах. Две-три строки, без таблицы.

### 2. Кандидаты на остановку

CPL по Facebook выше порога гео. По каждой: название, гео, открут, лиды, CPL, порог,
превышение в процентах, **сколько дней подряд держится выше порога**.

Дни подряд — важнее разового превышения: один плохой день бывает у рабочей связки.

Обязательная приписка под блоком: *это данные Facebook, реальный CPL по трекеру может
быть ниже.*

### 3. Кандидаты на долив

CPL ниже цели **и** частота ниже 1.5. По каждой: текущий дневной бюджет, CPL, частота,
охват, оценка запаса аудитории.

Частота ниже 1.5 означает, что аудитория ещё не увидела объявление по второму разу —
есть куда расти без роста цены.

### 4. Выгорание

Кампании, где за неделю одновременно: **частота выросла**, **CPL пополз вверх**,
**outbound CTR пополз вниз**. Все три признака вместе, не по отдельности.

Это те, кому нужен **новый креатив, а не новый бюджет**. Долив сюда только ускорит
падение. Считать по дневной разбивке `time_increment: "1"`, сравнивая первые три дня
недели с последними тремя.

### 5. Тревожные сигналы

- рост CPM или CPC против вчера и против недели
- кампании без единого результата при откруте выше $15
- кампании со словом `TEST`, отработавшие второй день
- частота выше 1.8
- падение outbound CTR

### 6. Сводная таблица

`кампания — гео — открут — лиды — CPL — цель/порог — вердикт`

Вердикт словом: *в норме*, *кандидат на остановку*, *кандидат на долив*, *выгорает*,
*нет данных*.

## Тон

Компактно, без воды. **Если всё в норме — так и написать**, не растягивая на страницу.

Не предлагать выключить. Формулировка «кандидат на остановку» — это доклад,
а не рекомендация к действию.

## Если коннектор недоступен

Сказать прямо: коннектор Facebook ADS недоступен, данных нет.
**Не выдумывать цифры ни при каких условиях.** Проверить и показать `enabledInChat`
через `ListConnectors`, чтобы владелец видел причину.

## Контекст, который стоит помнить при чтении цифр

**Outbound CTR и all-CTR расходятся в 5–7 раз** (2.8–6.1% против 20–40%). Это норма
для этой вертикали: 80–89% «кликов» — раскрытия «Ещё» и тапы по картинке. Судить
о переходах только по `outbound_clicks_ctr`.

**LPV сломан.** 25 592 клика → 61 landing page view → 558 лидов. Середина воронки
невидима, на `omni_landing_page_view` не опираться.

**Тест кампании стоит $30–40, не больше.** Кампания, открутившая $15 без результата, —
это ожидаемая ситуация в 22% случаев даже у рабочей связки, поэтому один нулевой день
ничего не доказывает. Два подряд — уже 5%.
